# Thymus

Нативное Android-приложение: локальный MTProto-прокси,
который гоняет трафик Telegram через WebSocket к серверам Telegram.

```
Telegram (на телефоне) → 127.0.0.1:1443 → WebSocket (TLS) → DC Telegram
```

Приложение поднимает прокси **только на loopback-интерфейсе**, поэтому:
- не нужен VPN, root и сторонние серверы;
- трафик не выходит за пределы устройства иначе как в Telegram;
- данные остаются в том же шифровании MTProto — прокси лишь меняет транспорт.

## Возможности

- Нативный Kotlin/Compose, без Python.
- Сам MTProto-прокси работает без VPN. Отдельный необязательный режим обхода DPI
  (YouTube, Discord) использует локальный `VpnService` — см. раздел ниже.
- Главный экран — крупная кнопка **Включить/Выключить**, кнопка **Подключить** с иконкой
  Telegram, шестерёнка настроек и карточка трафика ↓/↑ внизу.
- MTProto-прокси на `127.0.0.1:1443` (порт и секрет настраиваются).
- Три маршрута до DC: WebSocket напрямую, WebSocket через Cloudflare-домены, обычный TCP.
  Первое подключение к DC запускает прямой и Cloudflare-маршрут одновременно и берёт тот,
  что ответил раньше; рабочий маршрут запоминается отдельно для каждого DC.
- Пул готовых соединений: после подключения приложение заранее открывает запасной
  TLS+WS-туннель (TTL 20 с), поэтому следующее переподключение Telegram не платит
  0.5–1.8 с за рукопожатие. На замерах первое подключение 390 мс, из пула — 110 мс.
  Если сервер закрывает такой туннель, пул автоматически отключается на минуту.
- Прогрев маршрутов при запуске идёт в фоне и не блокирует интерфейс.
- Cloudflare-домены: параллельный перебор, «мёртвые» (503) уходят в карантин на 5 минут,
  список автоматически обновляется с GitHub при запуске.
- DNS с защитой от подмены: если адрес CF-домена не принадлежит Cloudflare,
  имя переразрешается через DNS-over-HTTPS (1.1.1.1 / Cloudflare / Google / Quad9).
- Слушает и `127.0.0.1`, и `::1` (на случай, если клиент открывает `localhost`).
- Разбор obfuscated-handshake, AES-CTR перешифровка потоков, разбиение на WS-фреймы по пакетам.
- Foreground-сервис без уведомления: приложение не запрашивает разрешение на уведомления,
  поэтому на Android 13+ в шторке нет ни строки, ни иконки. Сервис виден только в системном
  «Диспетчере задач» (свёрнутые приложения).
- Встроенный лог, статистика и проверка маршрутов с замерами времени и локальным тестом пинга.
- Обход блокировок YouTube и Discord без root: локальный VPN, разбиение TLS-рукопожатия
  внутри SNI и отключение QUIC.

## Сборка

Требуется JDK 17+ и Android SDK (platform 35, build-tools 35).

```bash
# путь к SDK
echo "sdk.dir=/path/to/Android/Sdk" > local.properties

./gradlew test assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

Готовые APK уже собраны: `dist/Thymus-1.0.2.apk` (release, подписан debug-ключом)
и `app/build/outputs/apk/debug/app-debug.apk`.

Проверка ядра на реальном DC Telegram (нужен доступ к Telegram):

```bash
./gradlew test -Dtgws.netTest=1
```

Тест поднимает настоящий `ProxyEngine`, подключается к нему как клиент Telegram,
проксирует `req_pq_multi` через WebSocket и ждёт `resPQ`.

`PacketTests` и `TcpRelayTest` проверяют обход DPI без телефона: контрольные суммы
IPv4/TCP/UDP/ICMP, MSS в SYN-ACK, разбиение ClientHello по SNI и повторную отправку
сегментов, которые устройство не подтвердило.

Release-сборка подписывается debug-ключом, если рядом нет `keystore.properties`:

```properties
storeFile=/path/to/release.jks
storePassword=...
keyAlias=...
keyPassword=...
```

Либо соберите APK в GitHub Actions (workflow `Build APK`) и скачайте артефакт.

## Использование

1. Установите APK и откройте Thymus.
2. Нажмите **Включить**.
3. Нажмите **Подключить** и подтвердите добавление прокси.
   Вручную: Настройки → Данные и память → Прокси → MTProto, сервер `127.0.0.1`,
   порт из приложения, секрет с префиксом `dd`.
4. В **Настройках** отключите оптимизацию батареи, чтобы система не убивала сервис в фоне.

Ссылку можно отправить себе в «Избранное» и открыть на телефоне — Telegram сам предложит
подключить прокси.

## Обход блокировок YouTube и Discord

В **Настройках** есть раздел «Обход блокировок». Он не связан с MTProto-прокси и работает
независимо: приложение поднимает локальный VPN и перехватывает трафик устройства.

- Корневые права не нужны.
- TLS-рукопожатие разбивается на два TCP-сегмента внутри имени SNI, поэтому DPI,
  который ищет заблокированный домен в одном пакете, его не видит.
- QUIC (UDP 443) не пропускается: клиент получает ICMP «порт закрыт» и сразу
  переходит на TCP, где работает разбиение.
- DNS и остальной UDP идут через тот же туннель, а DNS-серверы берутся у текущей
  сети — публичные 1.1.1.1 используются только как запасной вариант.
- Сам Thymus и Telegram исключены из туннеля: прокси на `127.0.0.1` и дальше
  ходит напрямую, поэтому обход не замедляет мессенджер.
- IPv6 не перехватывается: туннель только IPv4. Приложения, которые ходят по IPv6,
  обход не затрагивает.

Что важно знать:

- При первом включении Android спросит разрешение VPN. Без него режим не запустится.
- Одновременно с другим VPN-приложением это работать не будет — Android разрешает
  только один активный VPN.
- Это не полная реализация zapret: без root нельзя отправлять поддельные пакеты и играть с TTL.
  Доступно только разбиение TLS и отключение QUIC. Если провайдер блокирует и это,
  режим не поможет — выключите его.
- Windows-сборка `zapret-discord-youtube` использует WinDivert и `.bat`-скрипты,
  её binaries в Android встроить нельзя; здесь реализована та же идея нативно.

## Если не подключается

1. Откройте **Настройки** → раздел «Лог» и нажмите **Проверить маршруты**. Через ~20 секунд появится строка на каждый DC
   и результат локального теста:

   ```
   DC2: WS ✓ kws2.web.telegram.org@149.154.167.220 480 мс · CF ✓ kws2.offshor.co.uk 650 мс · TCP ✗ ...
   DC1: WS ✗ timeout · CF ✓ kws1.offshor.co.uk 700 мс · TCP ✗ ...
   Локальный тест DC2: ответ за 1.2 с, пинг 140 мс
   ```

   - `WS ✓` — прямой маршрут до DC работает (самый короткий путь);
   - `CF ✓` — работает обход через Cloudflare (нужен, если прямой заблокирован);
   - `TCP ✗ timeout` — обычный TCP до DC закрыт (это нормально, если работает CF);
   - `ответ за …` — сколько ждёт Telegram при **новом** подключении (выбор маршрута + TLS);
   - `пинг …` — установившееся время отклика, именно его показывает Telegram в настройках прокси.

2. Если пинг в Telegram сильно больше локального теста — дело не в маршруте: проверьте,
   что прокси в Telegram добавлен с текущим секретом, и что приложение не выгружается системой.

3. Если оба маршрута `✗`, сеть блокирует и Telegram, и Cloudflare. Попробуйте другую сеть
   или свои CF-домены в настройках.

4. `Неверный handshake` в логе и красная карточка — Telegram подключается со старым секретом.
   Удалите лишнюю запись `127.0.0.1:1443` в настройках прокси Telegram, оставьте одну.

5. В Telegram не должно быть **двух** записей `127.0.0.1:1443`. Если одна из них висит
   в статусе «Проверка…», удалите её: Telegram будет бросать подключения то на рабочий
   прокси, то на запись со старым секретом, и соединение будет рваться. Оставьте одну
   запись с текущим секретом. Автопереключение прокси при этом лучше выключить.

6. Если Android показывал «Приложение не отвечает» — это исправлено в 1.0.2:
   проверка маршрутов при старте больше не выполняется на главном потоке.

7. «Скопировать лог» — копирует последние строки, удобно приложить к описанию проблемы.

## Если фото/видео не грузятся

в настройках прокси в Telegram (DC → IP) оставьте только
`4:149.154.167.220` либо очистите поле. Поле «DC → IP» в настройках приложения
задаёт, какие DC идут через WebSocket; остальные уходят в TCP/CF-резерв.
Если оставить это поле пустым, прямой WebSocket не используется вовсе — работают
только Cloudflare и TCP.

## Ограничения

Не перенесено: HTTP/2-мультиплексирование для медиа, Cloudflare Worker, Fake TLS
(на loopback не нужен — клиент и прокси на одном устройстве), PROXY protocol.
Список CF-доменов обновляется с GitHub при запуске (если поле не переопределено вручную).

Проект не связан с Telegram. Используйте на свой риск и в рамках закона.
