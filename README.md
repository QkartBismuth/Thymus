# Thymus

[![Build APK](https://github.com/QkartBismuth/Thymus/actions/workflows/build.yml/badge.svg)](https://github.com/QkartBismuth/Thymus/actions/workflows/build.yml)

Нативное Android-приложение: локальный MTProto-прокси, который гоняет трафик Telegram
через WebSocket к серверам Telegram.

```
Telegram (на телефоне) → 127.0.0.1:1443 → WebSocket (TLS) → DC Telegram
```

Приложение поднимает прокси **только на loopback-интерфейсе**, поэтому:
- не нужен VPN, root и сторонние серверы;
- трафик не выходит за пределы устройства иначе как в Telegram;
- данные остаются в том же шифровании MTProto — прокси лишь меняет транспорт.

**Скачать:** [последний APK](https://github.com/QkartBismuth/Thymus/releases/latest) · Android 8.0+

## Возможности

- Нативный Kotlin/Compose, без Python.
- Сам MTProto-прокси работает без VPN. Отдельный необязательный режим обхода DPI
  использует локальный `VpnService` и помогает только при поверхностной фильтрации —
  см. раздел ниже.
- Главный экран — крупная кнопка **Включить/Выключить**, кнопка **Подключить** с иконкой
  Telegram, шестерёнка настроек и карточка трафика ↓/↑ внизу.
- MTProto-прокси на `127.0.0.1:1443` (порт и секрет настраиваются).
- Три маршрута до DC: WebSocket напрямую, WebSocket через Cloudflare-домены, обычный TCP.
  Первое подключение к DC запускает прямой и Cloudflare-маршрут одновременно и берёт тот,
  что ответил раньше; рабочий маршрут запоминается отдельно для каждого DC.
- Пул готовых соединений: после подключения приложение заранее открывает запасной
  TLS+WS-туннель (TTL 20 с), поэтому следующее переподключение Telegram не платит
  0.5–1.8 с за рукопожатие. На замерах первое подключение 390 мс, из пула — 110 мс.
  Если сервер закрывает такой туннель, пул автоматически отключается на минуту.
- Прогрев маршрутов при запуске идёт в фоне и не блокирует интерфейс.
- Cloudflare-домены: параллельный перебор, «мёртвые» (503) уходят в карантин на 5 минут,
  список автоматически обновляется с GitHub при запуске.
- DNS с защитой от подмены: если адрес CF-домена не принадлежит Cloudflare,
  имя переразрешается через DNS-over-HTTPS (1.1.1.1 / Cloudflare / Google / Quad9).
- Слушает и `127.0.0.1`, и `::1` (на случай, если клиент открывает `localhost`).
- Разбор obfuscated-handshake, AES-CTR перешифровка потоков, разбиение на WS-фреймы по пакетам.
- Foreground-сервис без уведомления: приложение не запрашивает разрешение на уведомления,
  поэтому на Android 13+ в шторке нет ни строки, ни иконки. Сервис виден только в системном
  «Диспетчере задач» (свёрнутые приложения).
- Встроенный лог, статистика и проверка маршрутов с замерами времени и локальным тестом пинга.
- Экспериментальный обход DPI без root: локальный VPN, переупаковка TLS-рукопожатия
  внутри SNI, ретрансляция QUIC и выбор конфига, как в zapret. Не помогает против
  глубокой инспекции.
- Автоподбор конфига обхода: проверяет каждый конфиг реальным TLS-рукопожатием с
  YouTube и Discord и оставляет тот, что получил ответ.

## Оформление

Ботаническая палитра из референса: лавандовый `#B99AEF`, светлая лаванда `#EDE5FB`,
хвойный зелёный `#0E4B4A`, молочный белый `#FDFCF8`, шампань `#D8D6A6`.
Иконка приложения собрана из `Thymus.png` (adaptive icon для Android 8+ и обычные PNG
для старых лончеров). Главный экран повторяет `referens.jpg`: фон `backround.png` на весь
экран, шестерёнка в правом верхнем углу, большая кнопка питания, пилюля «Подключить» с
`telegram_icon.svg` и карточка трафика внизу; иконка настроек — `settings_icon.svg`.
Тема переключается в **Настройки → Тема**: светлая (лавандовый день) и тёмная по
`referens_dark.jpg` — ночной фон `backround_dark.png`, более светлый хвойный, кремовый
текст и пурпурная панель трафика `#64457E`. Выбор запоминается, системные иконки
подстраиваются под тему.
Шрифт — [Geologica](https://github.com/google/fonts/tree/main/ofl/geologica). Кегли по референсу:
кнопка питания 32 sp, «Подключить» 17 sp, значения трафика 21 sp — все Bold.

## Сборка

Требуется JDK 17+ и Android SDK (platform 35, build-tools 35).

```bash
# путь к SDK
echo "sdk.dir=/path/to/Android/Sdk" > local.properties

./gradlew test assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

Готовый APK — в [Releases](https://github.com/QkartBismuth/Thymus/releases/latest)
(`v1.0.2`, release-сборка, подписана debug-ключом). CI также собирает APK на каждый
push: workflow `Build APK`, артефакт `thymus-apk`.

Проверка ядра на реальном DC Telegram (нужен доступ к Telegram):

```bash
./gradlew test -Dtgws.netTest=1
```

Тест поднимает настоящий `ProxyEngine`, подключается к нему как клиент Telegram,
проксирует `req_pq_multi` через WebSocket и ждёт `resPQ`.

`PacketTests` и `TcpRelayTest` проверяют обход DPI без телефона: контрольные суммы
IPv4/TCP/UDP/ICMP, MSS в SYN-ACK, переупаковку ClientHello в одну или несколько
TLS-записей с разрезом внутри заблокированного слова и OOB-байтом, фильтр по хостам,
подавление дублей и повторную отправку сегментов, которые устройство не подтвердило.
`BypassConfigParserTest` проверяет разбор zapret `.bat`, собственного `.conf` и
округление неподдерживаемых приёмов до `split` + `oob`.

Release-сборка подписывается debug-ключом, если рядом нет `keystore.properties`:

```properties
storeFile=/path/to/release.jks
storePassword=...
keyAlias=...
keyPassword=...
```

Либо соберите APK в GitHub Actions (workflow `Build APK`) и скачайте артефакт.

## Использование

1. Установите APK и откройте Thymus.
2. Нажмите **Включить**.
3. Нажмите **Подключить** и подтвердите добавление прокси.
   Вручную: Настройки → Данные и память → Прокси → MTProto, сервер `127.0.0.1`,
   порт из приложения, секрет с префиксом `dd`.
4. В **Настройках** отключите оптимизацию батареи, чтобы система не убивала сервис в фоне.

Ссылку можно отправить себе в «Избранное» и открыть на телефоне — Telegram сам предложит
подключить прокси.

## Обход блокировок: что работает, а что нет

В **Настройках** есть раздел «Обход блокировок». Он не связан с MTProto-прокси и
работает независимо: приложение поднимает локальный VPN и перехватывает трафик
устройства. Корневые права не нужны.

Как это устроено:

- TCP-соединения завершаются внутри приложения и открываются заново обычным сокетом.
- Первый TLS ClientHello переупаковывается в две или несколько TLS-записей. Разрез
  проходит не по середине имени, а внутри самого заблокированного слова — как `midsld`
  в zapret: `youtubei.googleapis.com` превращается в `yout` + `ubei.googleapis.com`,
  поэтому ни один фрагмент не содержит целого слова. Между записями отправляется
  внеполосный байт (`oob`): TCP-стек сервера его выбрасывает, а DPI, который пытается
  собрать записи обратно, теряет рукопожатие.
- QUIC (UDP 443) не отбрасывается, а ретранслируется: SNI внутри QUIC зашифрован,
  поэтому фильтр по имени хоста его не видит. DNS и остальной UDP идут через тот же
  туннель, а DNS-серверы берутся у текущей сети — публичные 1.1.1.1 только как запасной
  вариант.
- Сам Thymus и Telegram исключены из туннеля: прокси на `127.0.0.1` и дальше ходит
  напрямую, поэтому обход не замедляет мессенджер.
- IPv6 не перехватывается: туннель только IPv4. Приложения, которые ходят по IPv6,
  обход не затрагивает.

### Конфиги обхода

В разделе «Обход блокировок» можно выбрать конфигурацию, как в zapret, или загрузить
свою. Выбор запоминается и применяется к новым соединениям сразу; уже открытые
загрузки не рвутся.

Встроенные конфиги повторяют логику одноимённых `.bat`:

- **General** — OOB + разрез внутри слова (`midsld`), проверен на ТСПУ;
- **General (ALT)** — `multisplit` 1 + middle + midsld;
- **General (ALT2)** — `multisplit` 1 + midsld;
- **General (FAKE TLS AUTO)** — OOB + midsld;
- **General (SIMPLE FAKE)** — split 1 + OOB;
- **General (EXP)** — `multisplit` 1 + midsld;
- **Split only** — две TLS-записи без OOB;
- **OOB (single split)** — OOB + разрез посередине имени;
- **Pass-through** — VPN без изменения рукопожатия.

### Автоподбор конфига

Кнопка **«Подобрать автоматически»** проверяет каждый конфиг на реальных серверах. Для
`www.youtube.com`, `youtubei.googleapis.com` и `discord.com` системный TLS-стек собирает
настоящий ClientHello, к нему применяется разрез выбранного конфига, и рукопожатие
отправляется на сервер. Ответ ServerHello означает, что конфиг прошёл фильтр.

Конфиги проверяются параллельно; для каждого считается, сколько целей ответило, и
средняя задержка. Побеждает конфиг с наибольшим числом ответов, при равенстве — с
меньшей задержкой. Он сразу сохраняется и применяется к новым соединениям. Если VPN
включён, сокеты проверки исключены из туннеля, поэтому измеряется именно конфиг, а не
уже работающий обход.

Проверка занимает до ~10 секунд. Если ни один конфиг не получил ответ, приложение
скажет об этом: значит, блокировка не по SNI (например, по IP) или сеть недоступна.

Кнопка **«Загрузить конфиг»** принимает два формата.

1. `.bat` из zapret (`winws.exe`). Читаются `--filter-tcp`, `--hostlist-domains`,
   `--dpi-desync`, `--dpi-desync-split-pos` и `--dpi-desync-repeats`. Всё, что требует
   root (`fake`, `badseq`, `multidisorder`, `hostfakesplit`, `split-seqovl`, `ip-id`,
   `filter-l7`), заменяется разрезом и OOB-байтом; в карточке конфига видно, что учтено
   не полностью. Списки доменов из `%LISTS%` прочитать нельзя, поэтому такой конфиг
   применяется ко всем именам.
2. Собственный `.conf`:

   ```properties
   name=Мой конфиг
   description=OOB + midsld
   desync=multisplit,oob
   split-pos=1,midsld
   oob=1
   repeats=2
   ports=443
   hosts=youtube.com,youtubei.googleapis.com
   quic=relay
   ```

   `split-pos` принимает `midsld` (внутри слова), `middle` (середина имени), `host`
   (начало имени) или число байт. `quic=drop` отбрасывает UDP 443, чтобы клиент перешёл
   на TCP.

Импортированные конфиги хранятся в приватной папке приложения (`files/bypass/*.conf`)
и удаляются в том же списке. Файлы из `Downloads` после импорта не нужны.

Проверка на Tele2 (октябрь 2026, ТСПУ):

- Без обхода любой TLS-хендшейк с SNI `www.youtube.com`, `youtubei.googleapis.com`,
  `discord.com` или `gateway.discord.gg` обрывается; QUIC на UDP 443 не отвечает.
- С включённым обходом (`oob` + разрез внутри слова) `https://www.youtube.com/`,
  `https://youtubei.googleapis.com/`, `https://i.ytimg.com/` и
  `https://discord.com/api/v10/gateway` отвечают `200`/`204`. Приложение YouTube
  показывает ленту и проигрывает видео, Discord загружает каналы и вложения.
- Раньше не помогали: разбиение ClientHello по TCP, две TLS-записи с разрезом по
  середине имени и смена IP. Помог именно разрез внутри слова: если резать
  `youtubei.googleapis.com` посередине, первый фрагмент `youtubei.goog` всё ещё
  содержит `youtube`, и фильтр его ловит.
- `redirector.googlevideo.com` по-прежнему не отвечает, но сами видео-CDNs
  (`*.googlevideo.com`) работают — видео играет.
- Блокировка по IP и полная сборка потока этим способом не обходятся.

Что важно знать:

- При первом включении Android спросит разрешение VPN. Без него режим не запустится.
- Одновременно с другим VPN-приложением это работать не будет — Android разрешает
  только один активный VPN.
- Это не полная реализация zapret: без root нельзя отправлять поддельные пакеты и играть с
  TTL и последовательностями (`fake`, `badseq`, `multidisorder`). Встроенные конфиги
  и импорт `.bat` заменяют эти приёмы доступными обычному сокету `split`, `oob` и
  разрезом внутри слова. Если провайдер блокирует по IP или собирает поток целиком —
  режим не поможет.
- Windows-сборка `zapret-discord-youtube` использует WinDivert и `.bat`-скрипты,
  её binaries в Android встроить нельзя; здесь реализована та же идея нативно.

## Если не подключается

1. Откройте **Настройки** → раздел «Лог» и нажмите **Проверить маршруты**. Через ~20 секунд появится строка на каждый DC
   и результат локального теста:

   ```
   DC2: WS ✓ kws2.web.telegram.org@149.154.167.220 480 мс · CF ✓ kws2.offshor.co.uk 650 мс · TCP ✗ ...
   DC1: WS ✗ timeout · CF ✓ kws1.offshor.co.uk 700 мс · TCP ✗ ...
   Локальный тест DC2: ответ за 1.2 с, пинг 140 мс
   ```

   - `WS ✓` — прямой маршрут до DC работает (самый короткий путь);
   - `CF ✓` — работает обход через Cloudflare (нужен, если прямой заблокирован);
   - `TCP ✗ timeout` — обычный TCP до DC закрыт (это нормально, если работает CF);
   - `ответ за …` — сколько ждёт Telegram при **новом** подключении (выбор маршрута + TLS);
   - `пинг …` — установившееся время отклика, именно его показывает Telegram в настройках прокси.

2. Если пинг в Telegram сильно больше локального теста — дело не в маршруте: проверьте,
   что прокси в Telegram добавлен с текущим секретом, и что приложение не выгружается системой.

3. Если оба маршрута `✗`, сеть блокирует и Telegram, и Cloudflare. Попробуйте другую сеть
   или свои CF-домены в настройках.

4. `Неверный handshake` в логе и красная карточка — Telegram подключается со старым секретом.
   Удалите лишнюю запись `127.0.0.1:1443` в настройках прокси Telegram, оставьте одну.

5. В Telegram не должно быть **двух** записей `127.0.0.1:1443`. Если одна из них висит
   в статусе «Проверка…», удалите её: Telegram будет бросать подключения то на рабочий
   прокси, то на запись со старым секретом, и соединение будет рваться. Оставьте одну
   запись с текущим секретом. Автопереключение прокси при этом лучше выключить.

6. Если Android показывал «Приложение не отвечает» — это исправлено в 1.0.2:
   проверка маршрутов при старте больше не выполняется на главном потоке.

7. «Скопировать лог» — копирует последние строки, удобно приложить к описанию проблемы.

## Если фото/видео не грузятся

В настройках прокси в Telegram (DC → IP) оставьте только
`4:149.154.167.220` либо очистите поле. Поле «DC → IP» в настройках приложения
задаёт, какие DC идут через WebSocket; остальные уходят в TCP/CF-резерв.
Если оставить это поле пустым, прямой WebSocket не используется вовсе — работают
только Cloudflare и TCP.

## Ограничения

Не реализовано: HTTP/2-мультиплексирование для медиа, Cloudflare Worker, Fake TLS
(на loopback не нужен — клиент и прокси на одном устройстве), PROXY protocol.
Список CF-доменов обновляется с GitHub при запуске (если поле не переопределено вручную).

Проект не связан с Telegram. Используйте на свой риск и в рамках закона.
